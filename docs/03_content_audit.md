# 原工程审计与迁移决策

## 1. 工程概况

- 客户端：Egret 5.2.8 + EUI + p2.js，TypeScript/ES5。
- 服务端：PHP + MySQL，仅有用户金币读取和更新接口。
- 美术：运行时图集、MovieClip 图集、源 PNG/JPG、音频和界面效果图。
- Godot 目标工程：4.7，GL Compatibility 渲染器。

## 2. 已完成内容

- 启动、加载、游戏、结算、重开流程。
- 弹射输入、P2 物理、单向平台、滚屏和对象复用。
- 71 个内容组合、9 个分数档位、36 条怪物参数、11 条平台参数。
- 怪物巡逻/伏击、道具拾取、生命、倒计时、分数、能量火箭。
- 微信登录、分享、开放数据域排行榜和广告接口的旧版接线。

## 3. 明确缺陷

| 级别 | 问题 | 迁移决策 |
|---|---|---|
| P0 | `playmc1/playmc2` 被资源表引用但实际缺失 | 仅迁移完整的 `playmc3`，移除无效引用 |
| P0 | PHP `updateegold` 请求错误地指向 `getUserGold.php`，监听也未注册 | 首版停用旧金币服务 |
| P1 | 怪物与平台碰撞第二个分支判断 `bodyB` 同时为两种 ID，永远不成立 | Godot 中按无序碰撞对统一处理 |
| P1 | `cfg_score_zuhe` 最后一档是 99999，常规游戏几乎不会进入 | 视为哨兵/无穷档；实现时让最高可达档延续 700 档，待策划确认 |
| P1 | 道具 1 护盾数值为 0 且资源名为空 | 已恢复 `hudun` 动画，设为 5000 ms，并从 300 分档开始作为候选掉落 |
| P1 | 商店配置存在但购买和库存代码已注释 | 不列入核心首版 |
| P2 | 冰面平台固定赋予向右速度，镜像时仍向右 | 按平台朝向决定滑动方向 |
| P2 | 倒计时字段初值 30、总时长 180，逻辑重开后采用 180 | 统一为 180 秒 |
| P2 | 多个类与字段拼写错误（如 `word`、`complate`、`despose`） | Godot 命名统一为英文语义名 |
| P2 | 配置备注为旧编码，部分说明无法直接显示 | 已根据代码恢复字段语义，以新文档为准 |

## 4. 数据质量

- JSON 配置均可解析。
- `cfg_zuhe` 中的怪物、平台引用需要自动外键校验。
- `cfg_score_zuhe` 中组合序列与道具序列应逐档等长；验证脚本将作为迁移实现的一部分持续运行。
- `cfg_shangcheng` 的 `toolid` 字段实际指向道具表，`cost` 暂无生效代码。

## 5. 范围边界

本次第一步完成设计基线、配置表与资源规整，不改变玩法代码，也不承诺旧服务可继续部署。Godot 编码阶段以这里的规则为准，微信能力后置到核心玩法可运行之后。
